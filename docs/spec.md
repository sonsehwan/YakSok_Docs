# 1. 기능 명세

**상태:** 2026-11-09 기준 코드와 `completed/`·`active/` 문서를 대조해 작성. 안정적인 기능 정의만 적고,
설계 판단과 근거는 각 장(괄호 안 번호)에 있다. 아직 안 한 일은 `todo.md`, 알려진 한계는 `tech-debt.md`.

YakSok은 복약 관리 앱이다. 사용자가 **약속(복약 일정)**을 만들면 정해진 시각에 푸시로 알려 주고, 약속을 친구와
공유하거나 채팅할 수 있으며, 근처 약국 검색·약국 상담·알약 식별을 지원한다. 회원은 두 종류다 —
`NORMAL`(일반)과 `DRUGSTORE`(약국 사장, 가입 때 소속 약국을 고른다).

## 1.1 사용자 / 인증

- **회원가입** — 일반/약국 두 유형(바텀시트에서 선택). 약국 회원은 약국 검색 화면에서 소속 약국을 고른다.
  이메일 소유 확인이 필수다: 코드 발송 → 검증 성공 시 이메일에 묶인 1회용 토큰 발급 → 가입 저장 직전에
  소비·대조한다(46장). 가입·로그인 API는 `/api/auth/*`(47장).
- **로그인** — 아이디(`loginId`) + 비밀번호(10장). 카카오 로그인도 지원한다: 처음이면 역할(일반/약국)과
  닉네임을 고르는 가입 화면을 거치고, 이메일이 겹치면 가입을 막고 기존 계정 연동을 안내한다(33장).
  기존 회원은 내 정보에서 카카오를 연동·해제할 수 있다(비밀번호가 없는 회원의 해제는 거절).
- **토큰** — 액세스/리프레시 JWT. 리프레시는 재발급 때마다 교체(로테이션)한다. 앱은 401을 받으면 재발급 후
  **한 번만** 재시도하고, 재발급까지 실패하면 저장된 인증 정보를 지우고 모든 화면을 로그인으로 돌려보낸다(8장).
  컨트롤러는 토큰의 사용자 id만 신뢰한다(요청 본문의 userId는 쓰지 않는다).
- **아이디 찾기 / 비밀번호 재설정** — 이메일로 받은 6자리 코드로 본인 확인. 재설정은 검증 후 받은 토큰으로
  새 비밀번호를 직접 설정한다(10장).
- **내 정보** — 닉네임 수정(중복 허용, 33.12), 이메일 읽기 전용 표시, 비밀번호 변경, 약국 회원의 소속 약국 변경,
  회원 탈퇴(채팅방 정리 포함, 4·9장).
- **설정** — 알림 수신 on/off(15장), 로그아웃(해당 기기의 푸시 토큰만 삭제, 2장).
- **푸시 토큰** — `user_devices`에 사용자 1 : 기기 N으로 저장한다. 로그인 때 토큰 기준으로 갱신하거나 새
  사용자에게 다시 연결한다(2장).

## 1.2 약속(복약 일정)

- **구성** — 제목, 복약 시작일, 복약일 수, 아침/점심/저녁(끼니별 시각), 복용 시점(식전/식후 등), 약 목록.
  약은 이름·이미지·1일 횟수·1회 투약량을 갖는다. 약속마다 `복약일 × 끼니 수`만큼 알림 항목(`Notification`)이
  생기고, 완료한 개수로 진행률(%)을 계산한다.
- **등록 방법 3가지** — 직접 입력 / 처방전 사진 / 약봉투 사진(바텀시트에서 선택). 사진은 카메라 또는
  앨범에서 받는다(43장). 처방전은 ML Kit OCR과 Gemini를 함께, 약봉투는 Gemini만 써서 약 정보를 추출하고
  입력 폼을 채운다. **추출 결과는 저장하지 않고 사용자가 확인·선택한 뒤 등록한다.** 이름으로 조회하지 못한
  약은 화면에 계속 표시한다(36·37장). AI 호출은 서버를 거치지 않고 앱이 Firebase AI SDK로 직접 하며
  App Check를 적용했다.
- **조회·수정·삭제** — 홈(날짜별 알림 목록 + 진행률), 약속 목록(내 약속 / 공유받은 약속 탭), 상세, 수정, 삭제.
  수정 시 일정이 바뀌면 알림이 다시 만들어진다(38장).
- **복용 완료·취소** — 홈의 체크박스 또는 푸시 알림의 버튼으로 처리한다. 다기기·공유 상대 화면은 푸시로
  자동 갱신된다(3장).

## 1.3 알림

- **복약 리마인더** — 서버 스케줄러가 매분 0초(`0 * * * * *`)에 실행되어, 예정 시각이 현재 분과 같고 아직
  복용하지 않은 알림을 `user_devices`의 모든 기기로 보낸다(`REMINDER`).
- **알림에서 바로 완료** — 알림의 "약속 완료" 버튼이 앱을 열지 않고 서버에 완료를 반영한다(`goAsync`, 3장).
  실패하면 토스트로 알린다. **"약속 미루기" 버튼은 재알림이 구현되지 않아 숨겨 두었다**(`todo.md` 6.3).
- **푸시 종류**(`FcmMessageType`) — `REMINDER`(복약), `TAKEN_ALERT`(공유 약속의 복용 완료, 저장한 상대에게),
  `REFRESH`(알림 없이 화면만 갱신), `CHAT`(채팅 메시지), `FRIENDSHIP`(친구 요청 받음·성립).
  채널은 복약 / 공유 완료 / 채팅 / 친구로 분리해, 한 종류를 꺼도 다른 알림이 같이 꺼지지 않는다.
- **수신 설정** — 사용자별 on/off(`User.notificationEnabled`). 발송 단일 지점(`PushSender`)에서 거른다(15장).
  Android 13+ 알림 권한은 메인 화면 진입 때 요청한다.
- **친구 요청 알림** — 알림에 수락/거절 버튼이 붙고, 앱을 열지 않고 처리한다(45.4).

## 1.4 공유

- **약속 공유** — 약속 상세 메뉴 "공유" → 친구 선택 → 그 친구와의 채팅방에 **공유 카드 메시지**를 보낸다
  (카드에는 약속명만 저장, 25장).
- **받는 쪽** — 카드의 "확인하기"로 상세를 열어 보고(공유 관계를 검증, 20장) 저장하면 약속 목록의
  "공유받은 약속" 탭에 나타난다. 공유한 친구별로 거를 수 있고 기본은 "전체"다(21장). 목록에서 빼도 원본은
  그대로다.
- **복용 완료 알림** — 공유 약속을 **저장한** 사람에게, 상대가 복용을 완료하면 푸시(`TAKEN_ALERT`)가 간다.

## 1.5 친구

- **친구 추가** — 이메일로 검색해 요청을 보낸다. QR로도 추가할 수 있다: 내 QR 발급/표시, 상대 QR 스캔(ZXing) →
  프로필 다이얼로그(관계에 따라 요청·수락·채팅하기 버튼)(17장).
- **요청 처리** — 받은 요청 다이얼로그에서 수락/거절. 상대가 이미 나에게 요청한 상태에서 요청을 보내면 자동
  수락된다(45.4).
- **친구 목록** — 항목을 누르면 프로필 다이얼로그("채팅하기"), 길게 누르면 삭제(31장). 요청을 받거나 친구가
  성립하면 푸시와 함께 목록·요청 배지가 실시간으로 갱신된다(45.4).

## 1.6 채팅

- **방 종류** — 친구 1:1 채팅과 **약국 상담**(일반 회원 ↔ 약국). 한 방의 참여자는 사용자 또는 약국으로
  다형화돼 있다. 약국 사장 계정은 채팅 탭에서 [친구 | 상담]을 전환한다(9·22장).
- **전송** — STOMP over WebSocket. 메시지의 보낸 사람은 방별 참여자 id + 이름 스냅샷이다(이메일 아님, 9장).
  이전 메시지는 REST로 조회한다. 약속 공유 카드도 메시지의 한 종류다.
- **안 읽은 메시지** — 참여자별 읽음 커서로 목록 배지와 방 안 구분선을 계산한다(42장).
- **알림** — 앱이 백그라운드일 때 `CHAT` 푸시. 보낸 사람과 현재 그 방을 보고 있는 사용자는 제외한다(45.5).
- **방 정리** — 목록에서 "나가기"는 내 참여자를 숨김 처리한다(참여 시각과 읽음 커서를 갱신해, 다시 들어와도
  이전 메시지는 보이지 않는다). 회원 탈퇴 때만 참여자를 지우고, 남은 참여자가 0명이면 방과 메시지까지 삭제한다.
  메시지가 없는 방은 목록에서 제외한다(9·44장). 방을 만들 때 실제 친구인지 검증한다.

## 1.7 약국 / 의약품

- **약국 검색** — 지역(시/도·시군구)과 이름으로 검색, 위치 기반 인근 약국 목록(거리 표시), 약국 상세.
  회원가입·내 정보의 약국 선택도 같은 검색 화면을 쓴다.
- **의약품 검색** — 이름으로 검색(`/api/medicine/search`)하고, 약 이름 하나로 간단 정보를 조회한다(`/search/pill`,
  AI가 추출한 약 이름을 실제 약 정보로 맞출 때 쓴다). 약속 등록의 약 선택에서 쓴다.
- 약국·의약품 데이터는 공공데이터포털(`apis.data.go.kr`) API를 서버가 프록시한다. 외부 호출 실패는 표준
  응답으로 변환한다(`ExternalApiException`).

## 1.8 기술 스택

| 영역 | 구성 |
|---|---|
| 앱 | Android(Java, XML, ViewBinding), minSdk 26 / targetSdk 36. Jetpack Navigation(하단 탭 5개를 호스트 Activity 1개 + Fragment로), Material, Retrofit 2 + OkHttp(Gson), Glide, Pretendard(ViewPump 주입), 라이트 모드 고정 |
| 앱 외부 연동 | FCM, Firebase AI(Gemini) + App Check, ML Kit(한국어 OCR), ZXing(QR), 카카오 SDK, StompProtocolAndroid + RxJava2, Play Services Location |
| 서버 | Java 21, Spring Boot 4.0.3, Spring Security, Spring Data JPA, MySQL, JJWT 0.12.6, WebSocket(STOMP), Spring Mail(SMTP), WebClient/RestClient, Firebase Admin 9.2.0 |
| 인프라 | AWS EC2 단일 인스턴스. `main` push 시 GitHub Actions가 jar를 빌드해 배포(테스트 게이트 없음) |
| 테스트 | 서비스 단위 테스트(Mockito): `YaksokService`, `ShareYaksokService`(38·39장). 그 외는 거의 없다 |
