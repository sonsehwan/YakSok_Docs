# 6. 구현 예정

**상태:** 2026-11-09 갱신 — 끝난 항목은 해당 장으로 옮겨 "완료"로 표시했고, 남은 항목은 현재 코드로 다시
확인했다. 각 항목의 설계는 착수할 때 정한다. 진행 중인 큰 작업은 6.6에 모았다.

## 6.1 계정 / 인증

### JWT 인증 도입 → 8장으로 이동 (완료)

백엔드(비밀번호 해시화, 토큰 발급, 필터, 컨트롤러 전환, `authenticated()` 강제)와 프론트엔드
(헤더 자동 첨부, 401 자동 재발급, 강제 로그아웃) 모두 코드 반영 완료. 설계 판단과 세부 내용은
8장 참고.

**함께 처리할 것 — 저장된 로그인 상태의 서버 검증.**
지금은 `SprefsManager.isLoggedIn()`(로컬 boolean)만 보고 메인 화면으로 넘어간다.
다른 기기에서 탈퇴했거나 DB가 초기화돼도 앱은 로그인 상태로 남는다.
JWT가 자리잡았으니 "저장된 토큰으로 /me를 호출해서 200이면 진입, 401이면 로그인 화면"으로
바꿀 수 있다. 8장이 끝나 착수 가능해졌으나 아직 미착수다(8.12 참고). 2026-11-09 확인: 서버에 `/me` 같은 조회
API가 없고, 앱은 여전히 `SprefsManager.isLoggedIn()`만 본다.

### 채팅 `sender` email→id 전환 → 9장으로 이동 (완료)

`chat_message.sender`(email)를 없애고 방별 참여자 id(`sender_participant_id`) + 이름 스냅샷(`sender_name`)으로
바꿨다. email이 STOMP payload에서 사라졌고 재가입·닉네임 변경이 과거 메시지에 영향을 주지 않는다. 다만
"보낸 사람이 정말 그 참여자 본인인가"를 STOMP 메시지마다 검증하는 일은 남아 있다(`tech-debt.md`).

### 아이디 찾기, 비밀번호 찾기 → 10장으로 이동 (완료)

`User`에 `loginId`를 추가해 로그인을 loginId로 바꾸고, email은 이메일 인증(6자리 코드)으로 본인 확인하는 데
쓴다. 아이디 찾기는 인증 후 loginId를 보여 주고, 비밀번호는 인증 뒤 받은 재설정 토큰으로 새 비밀번호를 직접
설정한다. 운영 DB 마이그레이션과 메일 발송까지 EC2에서 확인했다. 의도적으로 미룬 항목은 10.8과 `tech-debt.md`.

### 카카오 로그인 → 33장 (1차·기존 회원 연동 구현, 실기기 확인 완료)

약국 회원 포함, 처음 가입할 때 역할 선택. 로그인·가입, 기존 회원 연동·연동 해제, 닉네임 유니크 제거(33.12)까지
끝났다. **남은 것:** 아이디 찾기·비밀번호 재설정의 카카오 회원 처리(카카오 가입 회원에게 "카카오로 가입한 계정"
안내), 탈퇴 시 카카오 연결 끊기(보류, `tech-debt.md`). 설계 판단은 33장 참고.

### 탈퇴 실패 해결 → 4장으로 이동 (완료)

FK 제약 위반이 원인이었다. 4장 참고. 채팅방 정리만 기술 부채로 남았다(5장).

## 6.3 알림

### 알림 껐다 켜기 → 15장으로 이동 (완료)

서버에 설정을 저장해 발송 단계에서 거르는 방식으로 정했다(`User.notificationEnabled`, `PushSender` 단일 지점).
설정 화면의 스위치로 켜고 끈다. 알림 채널은 복약 / 공유 완료 / 채팅 / 친구로 나뉘어 있다.

### 약속 미루기 구현

푸시 알림의 [약속 미루기] 액션 버튼은 지금 **숨겨져 있다**
(`MyFirebaseMessagingService.showNotification`의 `snoozeIntent` 생성부와 `addAction` 한 줄이 주석 처리).
`ACTION_SNOOZE`가 Toast만 띄우고 재알림 예약은 하지 않아서, 시연·APK 체험 중에 "10분 뒤에
알려드릴게요"라고 해놓고 안 울리는 가짜 동작이 걸리는 것을 막기 위해서다.

**복구할 때 할 일:** 재알림을 실제로 예약한 뒤 주석을 푼다. `NotificationActionReceiver`의
`ACTION_SNOOZE` 분기는 그대로 남겨 뒀다(버튼이 없으니 도달하지 않는 코드).

**결정할 것:** 재알림을 어디서 예약할지.

- 앱(`AlarmManager`/`WorkManager`) — 서버 변경 없이 된다. 단 정확한 알람은 `SCHEDULE_EXACT_ALARM`
  권한이 필요하고, 기기 재부팅·다기기 상황에서 어긋난다.
- 서버(`NotificationScheduler`) — 스케줄러가 이미 `IsTakenFalse`를 발송하므로 "미룬 시각"
  필드를 두고 발송 조건에 넣는 방식. 다기기에서도 일관되지만 `Notification`에 컬럼과 API가 늘어난다.

### 앱 진입 시 권한 확인 → 알림 권한은 15장으로 이동 (완료)

`POST_NOTIFICATIONS` 런타임 요청은 `MainActivity` 진입 때 한다(15장). 위치·카메라 권한은 지금도 각 화면이
필요할 때 확인하며(`DrugStoreList`, `ImageSourceBottomSheet`, QR 스캔), 앱 진입 시 일괄 확인은 하지 않는다 —
사용자가 설정에서 중간에 권한을 뺄 수 있어 화면별 확인은 어차피 남겨야 한다.

### 공통 상단바 컴포넌트 (상단바 통일)

지금은 화면마다 `iv_back`(40dp) + `tv_header_title`(높이 60dp, 20sp, `#000000`) +
`view_divider`(`#F0F0F0`) 세 뷰를 복사해 붙여 쓴다(2026-11-09 기준 `tv_header_title`을 쓰는 레이아웃 12개).
`Toolbar`도 `<include>`도 쓰지 않는다.
`FriendList`처럼 뒤로가기 대신 `iv_menu`가 있는 화면도 있다. (화면 배경은 18장의 "화면 배경색
결정"으로 전부 `@color/white`로 통일돼 더 이상 화면별로 다르지 않다.)

**방식 후보:**

- `<include layout="@layout/view_top_bar"/>` — 레이아웃 파일 하나로 끝나고 내부 뷰 id를 그대로
  둘 수 있어 자바 코드 수정이 거의 없다. 단 ConstraintLayout에서 다른 뷰가 `@id/view_divider`에
  걸어둔 제약은 include 자신의 id로 바꿔야 한다(include 안쪽 뷰는 직접 자식이 아니라서).
- `MaterialToolbar` — 오른쪽 액션 버튼이 여러 개 필요해지면 고려.
- 커스텀 View 클래스 — 제목·뒤로가기 여부를 XML 속성으로 받을 수 있지만 클래스가 하나 늘어난다.

### 색상 종류 줄이기 (대부분 완료)

18장 디자인 시스템 리스킨을 거치며 하드코딩 hex가 **210곳 → 5곳**으로 줄었다(2026-11-09 확인). 남은 곳:
에러 문구 빨강 `#FF0000` 3곳(`activity_sign_up_drugstore`, `activity_sign_up_kakao`, `component_input`)과
죽은 코드인 `activity_share_yaksok_list`의 `#000000`·`#F0F0F0`. 맞는 역할 이름(`status_*` 등)으로 바꾸면 끝난다.

### 버튼·글자 크기 축소

`android:textSize`가 레이아웃 **60개 파일에 279곳** 직접 지정돼 있어(2026-11-09 확인) 한 번에 줄일 수 없다.
`type.xml`의 `TextAppearance.App.*`는 폰트만 지정하고 크기는 Material3 기본값을 따른다.

**방식:** 제목/본문/보조 몇 단계로 크기를 정해 `TextAppearance.App.*`에 `android:textSize`를
넣고, 레이아웃의 `textSize`를 그 스타일로 바꾼다. 색상 줄이기와 같은 파일을 훑으므로 함께 하면 좋다.

**주의:** 위 접근성 항목(고령 사용자 → 글자 크기)과 방향이 반대다. 얼마나 줄일지 정할 때 같이 본다.
버튼은 글자를 줄여도 터치 영역(48dp)은 유지한다.

### 알림 목록 제목 말줄임

`item_notification.xml`의 `tv_notification_name`(16sp, bold)에 `maxLines`/`ellipsize`가 없어
긴 제목이 줄바꿈되며 카드가 늘어난다. `MedicationAdapter`와 `NotificationMultiViewAdapter`가 같은
레이아웃을 쓰므로 이 파일 한 곳에 `maxLines="1"` + `ellipsize="end"`를 주면 둘 다 반영된다
(`item_chat_room.xml`의 `tv_room_name`과 같은 방식).
시스템 푸시 알림 제목(`MyFirebaseMessagingService`의 `setContentTitle`)은 OS가 자르므로 대상이 아니다.

### 채팅 목록 최신 메시지 두 줄까지

`item_chat_room.xml`의 `tv_last_message`가 `maxLines="1"` + `ellipsize="end"`다.
`maxLines`를 2로 바꾸면 두 줄 뒤에 말줄임이 붙는다.

**말줄임표 점 개수(4개 → 3개):** 코드에서 `"...."`를 직접 붙이는 곳은 찾지 못했다.
`ellipsize="end"`는 말줄임 문자 `…`(한 글자, 점 3개)를 쓴다. 점이 4개로 보인다면 잘린 위치 바로
앞 글자가 마침표라 `.…`가 됐거나, Pretendard의 `…` 글리프가 그렇게 보이는 경우일 수 있다.
어떤 메시지에서 그렇게 보이는지 기기에서 먼저 확인한다.

## 6.5 기능 보완

### 회원가입·내 정보 수정의 약국 리스트에 거리 표시

인근 약국 목록(`DrugStoreList` → `DrugStoreAdapter`)에서는 나와의 거리가 보이는데, 약국 검색(`FindDrugStore` →
`FindDrugStoreAdapter`)을 쓰는 `SignUp_DrugStore`·`SignUp_Kakao`·`MyInfo`의 약국 선택에서는 안 보인다.

거리 계산에 필요한 것은 `LocationUtil`에 이미 있다.
**위치 권한이 없을 때 어떻게 보여줄지**(거리 칸을 숨길지, "위치 확인 불가"로 둘지)를 정해야 한다.
회원가입 단계에서 위치 권한을 요구하는 것이 부담스러울 수 있다.

### 인근 약국 목록에서도 약국 검색

**결정할 것.** `FindDrugStore`는 주소 스피너(`spFirstAddress` 등)로 약국을 찾지만,
`DrugStoreList`("인근 약국 목록")는 상단바와 `RecyclerView`뿐이라 검색이 없다.

- 넣는다면 — 이미 불러온 인근 목록을 약국 이름으로 거르는 것(클라이언트 필터)이 가장 작다.
  인근 범위 밖까지 찾으려면 서버 검색이 필요한데, 그건 `FindDrugStore`가 하는 일과 겹친다.
- 안 넣는다면 — `DrugStoreList`에서 `FindDrugStore`로 가는 진입점만 두는 방법도 있다.

## 6.6 진행 중인 작업 · 다른 문서에서 관리하는 것

착수했거나 설계가 따로 있는 항목. 세부는 각 문서가 정본이다.

- **서버 통신 중 버튼 중복 클릭 방지** — `active/47-busy-buttons.md`. `BusyCallback`·`BaseActivity.busy`는 만들었고 로그인
  화면에만 적용했다(커밋 전). 나머지 29개 파일이 남아 있다.
- **알림을 눌렀을 때 해당 화면으로 이동** — `active/45-next-tasks-queue.md` 45.4 "다음". 복약 → 홈, 친구 → 친구 목록,
  공유 약속 → 공유 탭, 채팅 → 그 방. `MainActivity.EXTRA_TARGET_TAB`과 `onNewIntent`는 이미 있고, 앱이 꺼진 상태에서
  누르면 시작 화면이 `Login`이라 로그인 확인과 이어붙이는 것이 관건이다(지금은 채팅·`TAKEN_ALERT` 알림에 `contentIntent`가 없다).
- **회원정보 변경(닉네임 등)을 다른 화면·기기에 알리기** — 45.3. "누구에게"(내 다른 기기 / 친구·채팅 상대)부터 정해야 한다.
