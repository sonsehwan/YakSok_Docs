# 6. 구현 예정

**상태:** 목록만 정리됨. 각 항목의 설계는 착수할 때 정한다.

## 6.1 계정 / 인증

### JWT 인증 도입 → 8장으로 이동 (완료)

백엔드(비밀번호 해시화, 토큰 발급, 필터, 컨트롤러 전환, `authenticated()` 강제)와 프론트엔드
(헤더 자동 첨부, 401 자동 재발급, 강제 로그아웃) 모두 코드 반영 완료. 설계 판단과 세부 내용은
8장 참고.

**함께 처리할 것 — 저장된 로그인 상태의 서버 검증.**
지금은 `SprefsManager.isLoggedIn()`(로컬 boolean)만 보고 메인 화면으로 넘어간다.
다른 기기에서 탈퇴했거나 DB가 초기화돼도 앱은 로그인 상태로 남는다.
JWT가 자리잡았으니 "저장된 토큰으로 /me를 호출해서 200이면 진입, 401이면 로그인 화면"으로
바꿀 수 있다. 8장이 끝나 착수 가능해졌으나 아직 미착수(8.12 참고).

### 채팅 `sender` email→id 전환 (JWT sweep에 포함)

`ChatMessage.sender` / `ChatMessageDto.sender` / `chat_message.sender` 컬럼이 **email**을 저장한다.
`User`의 PK가 email이던 시절의 잔재이고, id 리팩터링(2~3장, user/yaksok/fcm 도메인) 때
채팅 도메인은 빠졌다. 현재 파이프라인이 email로 자기완결적이라 동작은 한다.

- 프론트 전송: `myEmail = getUserEmail()` → `new ChatMessage(roomId, myEmail, ...)`
- 저장: `chat_message.sender` 컬럼
- 조회: `userRepository.findByEmailIn(senders)` 로 닉네임 매핑
- 표시: `msg.getSender().equals(myEmail)` 로 내/상대 말풍선 구분 (`ChattingRoomAdapter`)

**문제:** ① 클라이언트가 `sender`를 직접 채워 보내 신뢰됨(사칭 가능) ② 탈퇴 후 같은 이메일로
재가입하면 과거 메시지가 새 계정 닉네임으로 재귀속 ③ 이메일이 STOMP 브로드캐스트 payload로
상대 클라이언트에 전달됨 ④ 나머지 코드와 불일치

**JWT 도입 시 자연스럽게 해결되는 이유:** WebSocket 인증이 붙으면 `@MessageMapping` 핸들러가
`Principal`에서 발신자 id를 읽고, 클라이언트는 `sender`를 아예 안 보낸다. subject를 불변 PK(id)로
잡으면 저장 컬럼도 `Long userId`로 가고 ②도 사라진다.

**따로 남는 작업:** 기존 `chat_message.sender` 데이터 마이그레이션(email → id).
`chat_message` ↔ `users` FK 추가 여부는 별도 스키마 결정.

**지금 email→id만 단독으로 바꾸지 않는 이유:** 프론트 전송/DTO/조회 쿼리/어댑터 비교를 전부
건드려야 하는데, JWT 때 어차피 같은 지점을 다시 건드린다. 두 번 하지 않는다.

비밀번호가 평문으로 저장되고 있는 문제(5장)도 이때 함께 본다.

### 아이디 찾기, 비밀번호 찾기 → 10장으로 이동 (계획 수립)

`User`에 `loginId`를 추가해 로그인을 loginId로 바꾸고, email은 이메일 인증(6자리 코드)으로
본인 확인하는 데 쓴다. 아이디 찾기는 인증 후 loginId를 화면에 표시, 비밀번호 찾기는
loginId + email 일치 + 코드 인증 후 임시 비밀번호를 이메일로 발송(해시 저장이라 복구가 아닌
재설정). 설계 판단·변경 범위·열린 결정은 10장 참고.

### 카카오 로그인 → 33장 (설계 확정, 백엔드 구현됨, 앱 구현 중)

약국 회원 포함, 처음 가입할 때 역할 선택. 1차(로그인·가입) / 2차(기존 회원 연동, 아이디 찾기·
비밀번호 재설정의 카카오 회원 처리)로 나눈다. 닉네임 유니크 제거(33.12) 포함. 선행이던 `UserRequest.password` 검증 누락은 해결됨(`tech-debt.md`).
설계 판단은 33장 참고.

### 탈퇴 실패 해결 → 4장으로 이동 (완료)

FK 제약 위반이 원인이었다. 4장 참고. 채팅방 정리만 기술 부채로 남았다(5장).

## 6.3 알림

### 알림 껐다 켜기

앱 안에서 알림 수신을 끌 수 있게 한다.

채널이 이미 둘로 나뉘어 있다(`MyFirebaseMessagingService.resolveChannelId`).

- `yaksok_channel` — 복약 리마인더
- `yaksok_share_channel` — 공유 약속의 복약 완료 알림

**결정할 것:** 어디서 끄게 할지.
안드로이드 시스템 설정으로 보내는 방식(채널별 on/off를 OS가 관리)과
서버에 설정을 저장해 발송 단계에서 거르는 방식이 있다.
전자는 구현이 거의 없고, 후자는 기기마다 따로 끄지 않아도 되지만 스키마와 API가 늘어난다.

### 약속 미루기 구현

푸시 알림의 [약속 미루기] 액션 버튼은 지금 **숨겨져 있다**
(`MyFirebaseMessagingService.showNotification`의 `snoozeIntent` 생성부와 `addAction` 한 줄이 주석 처리).
`ACTION_SNOOZE`가 Toast만 띄우고 재알림 예약은 하지 않아서, 시연·APK 체험 중에 "10분 뒤에
알려드릴게요"라고 해놓고 안 울리는 가짜 동작이 걸리는 것을 막기 위해서다.

**복구할 때 할 일:** 재알림을 실제로 예약한 뒤 주석을 푼다. `NotificationActionReceiver`의
`ACTION_SNOOZE` 분기는 그대로 남겨 뒀다(버튼이 없으니 도달하지 않는 코드).

**결정할 것:** 재알림을 어디서 예약할지.

- 앱(`AlarmManager`/`WorkManager`) — 서버 변경 없이 된다. 단 정확한 알람은 `SCHEDULE_EXACT_ALARM`
  권한이 필요하고, 기기 재부팅·다기기 상황에서 어긋난다.
- 서버(`NotificationScheduler`) — 스케줄러가 이미 `IsTakenFalse`를 발송하므로 "미룬 시각"
  필드를 두고 발송 조건에 넣는 방식. 다기기에서도 일관되지만 `Notification`에 컬럼과 API가 늘어난다.

### 앱 진입 시 권한 확인

지금은 각 액티비티가 필요할 때만 권한을 확인한다
(예: `DrugStoreList`가 위치 권한 요청). 앱 진입 시에도 한 번 확인하되,
**각 액티비티의 확인은 그대로 남긴다** — 사용자가 중간에 설정에서 권한을 뺄 수 있기 때문.

**착수 시 확인할 것:** `POST_NOTIFICATIONS`가 매니페스트에는 선언돼 있지만
**런타임 요청 코드를 찾지 못했다.** `targetSdk = 36`이므로 Android 13 이상에서는
런타임 요청 없이는 알림이 표시되지 않는다. 지금 테스트 기기에서 알림이 오는 것은
설정에서 수동으로 허용했거나 기기 버전이 낮아서일 수 있다.
**복약 알림이 조용히 안 뜨는 실패 모드**이므로 이 항목에서 가장 먼저 볼 것.

### 공통 상단바 컴포넌트 (상단바 통일)

지금은 화면마다 `iv_back`(40dp) + `tv_header_title`(높이 60dp, 20sp, `#000000`) +
`view_divider`(`#F0F0F0`) 세 뷰를 복사해 붙여 쓴다. `Toolbar`도 `<include>`도 쓰지 않는다.
`FriendList`처럼 뒤로가기 대신 `iv_menu`가 있는 화면도 있다. (화면 배경은 18장의 "화면 배경색
결정"으로 전부 `@color/white`로 통일돼 더 이상 화면별로 다르지 않다.)

**방식 후보:**

- `<include layout="@layout/view_top_bar"/>` — 레이아웃 파일 하나로 끝나고 내부 뷰 id를 그대로
  둘 수 있어 자바 코드 수정이 거의 없다. 단 ConstraintLayout에서 다른 뷰가 `@id/view_divider`에
  걸어둔 제약은 include 자신의 id로 바꿔야 한다(include 안쪽 뷰는 직접 자식이 아니라서).
- `MaterialToolbar` — 오른쪽 액션 버튼이 여러 개 필요해지면 고려.
- 커스텀 View 클래스 — 제목·뒤로가기 여부를 XML 속성으로 받을 수 있지만 클래스가 하나 늘어난다.

### 색상 종류 줄이기

`colors.xml`에 역할별 이름(`brand_*`, `page_bg`, `status_*`)이 이미 있고 "화면에서는 이 이름만
쓰면 색 변경이 이 파일 하나로 끝난다"는 주석까지 있지만, 레이아웃에는 하드코딩된 hex 색이
**45개 파일에 210곳** 남아 있다(`#000000`, `#999999`, `#F0F0F0`, `#FBC02D` 등).
회색만 봐도 `neutral_*`(따뜻한 계열)과 `#999999`(중립 회색)가 섞여 있다.

**할 일:** 쓰이는 hex를 모아 가까운 `neutral_*`/`brand_*`로 합치고, 맞는 역할 이름이 없으면
`colors.xml`에 추가한 뒤 레이아웃을 교체한다.

### 버튼·글자 크기 축소

`android:textSize`가 레이아웃 **53개 파일에 210곳** 직접 지정돼 있어 한 번에 줄일 수 없다.
`type.xml`의 `TextAppearance.App.*`는 폰트만 지정하고 크기는 Material3 기본값을 따른다.

**방식:** 제목/본문/보조 몇 단계로 크기를 정해 `TextAppearance.App.*`에 `android:textSize`를
넣고, 레이아웃의 `textSize`를 그 스타일로 바꾼다. 색상 줄이기와 같은 파일을 훑으므로 함께 하면 좋다.

**주의:** 위 접근성 항목(고령 사용자 → 글자 크기)과 방향이 반대다. 얼마나 줄일지 정할 때 같이 본다.
버튼은 글자를 줄여도 터치 영역(48dp)은 유지한다.

### 알림 목록 제목 말줄임

`item_notification.xml`의 `tv_notification_name`(17sp, bold)에 `maxLines`/`ellipsize`가 없어
긴 제목이 줄바꿈되며 카드가 늘어난다. `MedicationAdapter`와 `NotificationMultiViewAdapter`가 같은
레이아웃을 쓰므로 이 파일 한 곳에 `maxLines="1"` + `ellipsize="end"`를 주면 둘 다 반영된다
(`item_chat_room.xml`의 `tv_room_name`과 같은 방식).
시스템 푸시 알림 제목(`MyFirebaseMessagingService`의 `setContentTitle`)은 OS가 자르므로 대상이 아니다.

### 채팅 목록 최신 메시지 두 줄까지

`item_chat_room.xml`의 `tv_last_message`가 `maxLines="1"` + `ellipsize="end"`다.
`maxLines`를 2로 바꾸면 두 줄 뒤에 말줄임이 붙는다.

**말줄임표 점 개수(4개 → 3개):** 코드에서 `"...."`를 직접 붙이는 곳은 찾지 못했다.
`ellipsize="end"`는 말줄임 문자 `…`(한 글자, 점 3개)를 쓴다. 점이 4개로 보인다면 잘린 위치 바로
앞 글자가 마침표라 `.…`가 됐거나, Pretendard의 `…` 글리프가 그렇게 보이는 경우일 수 있다.
어떤 메시지에서 그렇게 보이는지 기기에서 먼저 확인한다.

## 6.5 기능 보완

### 회원가입·내 정보 수정의 약국 리스트에 거리 표시

`FindDrugStore`에서는 나와의 거리가 보이는데,
`SignUp_DrugStore`와 `MyInfo`의 약국 선택에서는 안 보인다.

거리 계산에 필요한 것은 `LocationUtil`에 이미 있다.
**위치 권한이 없을 때 어떻게 보여줄지**(거리 칸을 숨길지, "위치 확인 불가"로 둘지)를 정해야 한다.
회원가입 단계에서 위치 권한을 요구하는 것이 부담스러울 수 있다.

### 인근 약국 목록에서도 약국 검색

**결정할 것.** `FindDrugStore`는 주소 스피너(`spFirstAddress` 등)로 약국을 찾지만,
`DrugStoreList`("인근 약국 목록")는 상단바와 `RecyclerView`뿐이라 검색이 없다.

- 넣는다면 — 이미 불러온 인근 목록을 약국 이름으로 거르는 것(클라이언트 필터)이 가장 작다.
  인근 범위 밖까지 찾으려면 서버 검색이 필요한데, 그건 `FindDrugStore`가 하는 일과 겹친다.
- 안 넣는다면 — `DrugStoreList`에서 `FindDrugStore`로 가는 진입점만 두는 방법도 있다.
